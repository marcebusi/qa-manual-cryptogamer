# BUG-007 — Índice de vendedor round-robin persiste en localStorage entre usuarios

| Campo | Detalle |
|---|---|
| **ID** | BUG-007 |
| **Módulo** | Checkout — Selección de vendedor |
| **Severidad** | P3 — Menor |
| **Estado** | Abierto |
| **Fecha** | 2026-10-27 |
| **Reportado por** | Marcelo Busignani |

---

## Descripción

La función `pickRandomSeller()` usa `localStorage` para recordar el índice del último vendedor seleccionado (clave `lastSellerIdx`), implementando un round-robin. Sin embargo, este índice persiste entre sesiones y entre usuarios que usen el mismo dispositivo. Esto significa que la distribución de pedidos entre vendedores es por dispositivo, no por sesión de usuario.

---

## Pasos para reproducir

1. Abrir checkout y hacer clic en "Elegir al azar" → el vendedor seleccionado es el índice 0 (ej: "Carlos")
2. Cerrar modal sin completar
3. Iniciar sesión con otro usuario (o continuar como el mismo)
4. Abrir checkout y hacer clic en "Elegir al azar" nuevamente → selecciona el índice 1 (ej: "Laura")

El índice continúa incrementando indefinidamente basado en `lastSellerIdx` en localStorage.

---

## Resultado actual

```javascript
localStorage.getItem('lastSellerIdx') // → "3" (persiste entre usuarios y sesiones)
```

---

## Resultado esperado

El round-robin debería ser manejado por el backend (servidor), no por el cliente, para garantizar una distribución justa entre todos los usuarios de la plataforma, no solo de un dispositivo.

---

## Impacto

- **Negocio leve:** Un dispositivo siempre asigna al mismo vendedor si hay pocos usuarios activos, mientras que otro dispositivo nunca llega a los vendedores iniciales.
- **Fairness:** La distribución de leads entre vendedores no es equitativa a nivel plataforma.

---

## Causa raíz (análisis de código)

En `CheckoutModal.tsx`:

```typescript
const pickRandomSeller = () => {
  if (allSellers.length === 0) return
  const lastIdx = parseInt(localStorage.getItem('lastSellerIdx') ?? '-1', 10)
  const nextIdx = (lastIdx + 1) % allSellers.length
  localStorage.setItem('lastSellerIdx', String(nextIdx))  // ← persiste por dispositivo
  setSeller(allSellers[nextIdx])
  setStep('summary')
}
```

---

## Solución sugerida

Delegar el round-robin al backend mediante un endpoint como `GET /api/sellers/next`, que incremente un contador server-side y devuelva el próximo vendedor disponible. Esto garantiza distribución uniforme a través de todos los clientes.
